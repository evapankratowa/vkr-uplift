# Тикеты на доработку (к ТЗ v1.0, docs/dev/TZ.md)

Формат: зависимости указаны явно; каждый тикет завершается зелёными
`pytest` + `ruff` и коротким commit message. Порядок выполнения — сверху вниз,
T3 и T4 можно делать параллельно после T1.

---

## T1. CLI: команда `simulate`

**Цель:** `uplift simulate --config configs/sim_base.yaml --experiment configs/experiment.yaml`
прогоняет сетку дизайнов и сохраняет обучающие выборки.

**Сделать:** в `cli.py` заменить заглушку на вызов
`experiment.simulate.run_grid(cfg_sim, cfg_exp)`; результаты —
`data/interim/experiment_<params>_<date>.parquet` (именование как в
существующем файле), сводка по ячейкам сетки — stdout-таблицей
(число строк, ATE, итог A/A). Логирование этапов через `logging`,
уровень INFO.

**Приёмка:** команда завершается нулём на дефолтных конфигах; повторный
запуск с тем же seed даёт идентичный parquet (проверка хешем в тесте);
`--help` информативен.

## T2. CLI: команды `train` и `evaluate`

**Зависит от:** T1.

**Сделать:**
- `train`: читает выборку из `data/interim/` (или датасет по `--dataset`),
  обучает архитектуры из `configs/models.yaml` через `models.meta.build`,
  сериализует в `models_store/` (joblib), пишет манифест
  (модель, параметры, хеш конфига, дата).
- `evaluate`: считает метрики (`evaluation/metrics.py`, `ground_truth.py`,
  `policy.py`) по всем обученным моделям, пишет
  `output/tables/VKR_uplift_architectures_<date>.csv` и графики Qini
  в `output/figures/` (matplotlib, белый фон, RGB — требование пайплайна
  сборки документа).

**Приёмка:** имена и колонки выходных CSV совпадают с существующими
эталонами внутреннего репозитория (`output/tables/VKR_uplift_architectures_2026-10-01.csv`
— сверить набор колонок); графики открываются, без прозрачного фона.

## T3. Слой БД: загрузчик и `--source db`

**Зависит от:** ничего (после каркаса).

**Сделать:**
- Зависимости `psycopg[binary]`, `SQLAlchemy>=2` в `requirements.txt`.
- `src/uplift_system/db/` — модуль: строка подключения из `DATABASE_URL`
  (дефолт `postgresql://uplift:uplift@localhost:5432/uplift`), функция
  `load_raw(csv_path, conn)` с идемпотентной вставкой (ON CONFLICT DO NOTHING)
  в таблицы схемы `uplift` (`client`, `client_spend`, `client_cashback`,
  `communication_stats`, `observation_window`, `spend_category`).
- Справочник `spend_category` и окна `observation_window` заполняются
  из самих данных; нарушения CHECK (отрицательные суммы трат) — отказ
  с понятной ошибкой и номером строки.
- Команда `uplift db-load --csv data/raw/cashback_raw_2022-11-15.csv`.
- Источник ковариат для `train`/`evaluate`: флаг `--source db|file`
  (дефолт `file`); при `db` данные читаются тем же адаптером,
  что и файлы (общий интерфейс в `datasets/`).

**Приёмка:** `docker compose up db` + `uplift db-load` на фикстурном CSV
(1 000 синтетических строк) — контрольное число строк в таблицах сходится;
`train --source db` и `--source file` дают одинаковые метрики (тест,
`pytest.mark.docker`, скипается без БД).

**Важно:** DDL `db/001_init.sql` не менять — это артефакт главы 2.
Если схеме чего-то не хватает под загрузчик — оформить `db/002_*.sql`
отдельной миграцией и отметить в PR.

## T4. Модуль финансового эффекта `economics`

**Зависит от:** T2 (нужны оценённые стратегии).

**Сделать:** `src/uplift_system/economics/` + команда `uplift economics`.
- Входы: результаты `evaluate` (ценность стратегии из `policy.py`),
  `docs/cost_inputs.yaml`, ценность отклика — медиана банковского кэшбэка
  120 ₽ (константа из DATA_PASSPORT, параметризовать в `configs/campaign.yaml`).
- Расчёт на канал: эффект = N_инкр_откликов × ценность − N_контактов × цена_канала;
  порог uplift = цена / (ценность × доставляемость) при оплате за отправку,
  цена / ценность при оплате за контакт (формулы — DATA_PASSPORT, ЭКОНОМИКА).
- Три сценария цены SMS: источник 3,2 ₽; проиндексированная 5,75 ₽;
  пакетный тариф 30 ₽/абонент/мес. Все три строками в выводе, без выбора
  «правильного».
- Выход: `output/tables/VKR_uplift_economics_<date>.csv` + краткий
  stdout-вывод; бутстрап-ДИ по деньгам (уже есть `bootstrap_ci`).

**Приёмка:** ручной пересчёт одной строки (push, цена 0,125 ₽) из выходной
таблицы сходится; тест на формулы порога и на сценарии (3 строки SMS).

## T7. CLI: команда `check`

**Зависит от:** T1–T6.

**Сделать:** `uplift check --all` прогоняет `checks.runner.CheckRunner`
по всем карточкам проверок (включая контрольные числа DATA_PASSPORT как
ассерты с допусками), пишет отчёт в `checks/` (markdown + machine-readable
json), код возврата 0 только если все проверки зелёные или задокументированно
жёлтые.

**Приёмка:** отчёт содержит вердикт по каждой проверке и итоговый;
падение любой красной проверки → код возврата 1.
