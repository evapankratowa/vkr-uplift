# ТЗ на доработку кодовой части ВКР до публикуемого состояния

Версия 1.0, 2026-11-21. Исполнитель — кодинговая модель; задачи декомпозированы
в [TICKETS.md](TICKETS.md). Репозиторий — публичная копия `vkr_uplift_public`;
внутренний `VKR_uplift` не изменяется.

## 1. Контекст и цель

Система определения сегментов коммуникации клиентов банка на uplift-моделировании.
Ядро (генератор синтетики, адаптеры открытых RCT, метрики, модели, оценка
стратегий) реализовано и покрыто тестами: 48 passed, 5 xfailed. Рабочий контур
сейчас — ноутбуки `01–05`; CLI `src/uplift_system/cli.py` — заглушка
(`NotImplementedError`).

**Цель:** репозиторий воспроизводится с чистого клона одной командой
(`make all` или `docker compose up --build`) и даёт заявленный в README
результат без обращения к автору. Дедлайн — защита репозитория 2026-11-30.

## 2. Область работ

**Входит (в порядке приоритета):**

1. F1 — реализация CLI: команды `simulate`, `train`, `evaluate`,
   `select-segment`, `check` поверх существующих модулей.
2. F2 — слой БД: загрузчик `data/raw` → PostgreSQL (схема `uplift`,
   DDL `db/001_init.sql`) и команда `uplift db-load`; чтение входных данных
   из БД как альтернатива файлам (флаг `--source db|file`, по умолчанию `file`).
3. F3 — модуль финансового эффекта `economics` и команда `uplift economics`:
   ценность кампании = инкрементальные отклики × ценность отклика − контакты ×
   стоимость контакта; по каналам из `docs/cost_inputs.yaml`; оба сценария
   цены SMS (по источнику 3,2 ₽ и проиндексированная 5,75 ₽) и пакетный тариф
   30 ₽/абонент — как сценарии, вывод сводной таблицы в `output/tables/`.
4. F4 — доводка сборщика сегментов до зелёных тестов: снять 5 `xfail`
   в `tests/test_segments.py`, реализовав недостающее в `segments/`.
5. F5 — end-to-end: `make all` с чистого клона; фиксация золотых контрольных
   чисел результата (метрики на синтетике с seed из `configs/`) в
   `tests/test_golden.py` с допусками.
6. F6 — инфраструктура: проверка `docker compose up --build` на чистом образе;
   GitHub Actions (lint + test) на push.

**Не входит:** изменение методики (метрики, модели, DGP — заморожены),
реальные интеграции с Zeppelin/системой рассылок, изменение DDL без
согласования (схема — артефакт главы 2 ВКР), работа с сырыми данными
(выгрузка кэшбэка в репозитории отсутствует по лицензионным причинам;
загрузчик проверяется на синтетических фикстурах).

## 3. Архитектурные ограничения

- Существующие публичные интерфейсы модулей не ломать; 48 зелёных тестов
  должны остаться зелёными. Новый код — в новых модулях/функциях.
- Python 3.11, зависимости только из `requirements.txt` (для БД допустимо
  добавить `psycopg[binary]` и `SQLAlchemy` — зафиксировать версии).
- Стиль: `ruff check` и `ruff format --check` чистые; docstrings на русском,
  как в существующем коде.
- Воспроизводимость: все случайности параметризуются `seed` из `configs/`;
  абсолютные пути и машинно-специфичные настройки запрещены
  (критерий методички РАНХиГС).
- Тесты не требуют сырых данных и сети: фикстуры — `make_covariates_for_tests`
  и маленькие синтетические DataFrame; тест БД — против postgres в
  docker-compose (помечен `pytest.mark.docker`, пропускается без БД).
- Сырые строки данных модели не показывать: проверки — агрегатами
  (число строк, контрольные суммы, доли).

## 4. Приёмочные критерии (сводно)

1. `make install && make data && make all` в чистом клоне завершается нулём
   и создаёт артефакты `output/tables/`, `output/figures/`, `checks/`.
2. `docker compose up --build` на машине без предустановленного Python
   воспроизводит тот же результат; PostgreSQL поднимается с DDL
   `db/001_init.sql` (проверка: `psql -c '\dn'` показывает `uplift`, `uplift_dw`).
3. `uplift db-load` загружает фикстурный CSV в схему `uplift`;
   `uplift train --source db` даёт тот же результат, что `--source file`
   (сверка метрик побитово или в допуске 1e-12).
4. `uplift economics` пишет сводную таблицу по каналам со всеми тремя
   сценариями цены SMS; числа сходятся с ручным пересчётом по формуле
   из `docs/DATA_PASSPORT.md` (раздел ЭКОНОМИКА).
5. `pytest`: 0 failed, 0 xfail (кроме сознательно помеченных `docker`),
   `ruff` чистый; CI зелёный на push.
6. README «Статус» обновлён: все чекбоксы закрыты или честно оставлены
   с пояснением.
